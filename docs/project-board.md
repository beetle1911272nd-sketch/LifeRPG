# LifeRPG Project Board

## 状態の定義

- Backlog: 話し合い中、まだ着手していない
- Ready: 対応可能で、開始条件が揃っている
- In Progress: 実装または調査中
- Review: 実装完了、レビュー待ち
- Done: 完了済み

## Issue の基本要件

各 Issue には次の項目を含めることを推奨します。

- 目的と背景
- 対象範囲
- 完了条件
- 関連する他の Issue/PR
- 担当者

## Unity / iOS 初回リリースの MVP 案

この案は、既存のWeb/PWAとGodotプロトタイプを比較して、Unityで再実装するiOS版の初回リリース範囲を絞ったものです。既存アプリの機能選定であり、Unityの技術構成や未確認のiOS要件を決定するものではありません。

### MVPの中心

**現実の行動を記録し、成長を実感するライフログRPG**を初回リリースの核とします。Web版の「行動 → EXP → レベル」の流れは製品目的に直結し、3Dゲームよりもスマートフォンで短時間・反復して使う用途に適しています。

- 初回プロフィール設定。既存Web版の目標入力と質問による職業診断（勇者・賢者・剣士など）を優先し、新しいジャンル選択肢は追加しない。確認したWebソースに独立したジャンル選択画面は見当たらないため、職業診断を既存の個性付けとして扱う。
- 行動候補を選び、実行を記録する。まずは既存アクションと完了記録を軸にし、記録ごとの獲得EXPを確認できるようにする。
- EXP、レベル、次のレベルまでの進捗を表示し、記録に応じてレベルアップする。
- 毎日のクエストを表示し、行動記録から進捗・達成報酬を更新する。
- 行動した日をもとに連続日数を記録し、今日の達成状態を分かりやすく示す。
- 端末内に自動保存し、アプリ再起動後も進行を復元する。保存データのバージョンと移行を扱い、ユーザーが退避・復元できる手段を用意する。
- オフラインでも記録と保存ができることを基本とする。

### 後回しにする範囲

- Supabaseアカウント連携、複数端末同期、ランキング、フレンド、ギルド、メッセージなどのオンライン・ソーシャル機能。Web版には実装があるが、認証・競合解決・運用の負担を初回リリースに持ち込まず、ローカル保存の信頼性を先に確認する。
- Godot版の3Dフィールド探索、戦闘、敵の再出現、ドロップ、インベントリ、装備、露店。これらは独立したゲームの遊びであり、現実の行動記録というMVPの中心に必須ではない。
- ダンジョン、戦術バトル、ガチャ、装備収集、複雑な戦闘ステータスやジョブ別成長。Web版の既存システムをそのまま移植せず、初回の行動・EXP・レベル体験に必要かを後から検証する。
- プッシュ通知、WidgetKitなど、iOSネイティブ機能の採用判断。要件・実装方式は別途確認して決める。

### 既存プロトタイプとの対応

| 領域 | Web/PWA | Godot | Unity / iOS MVPでの扱い |
| --- | --- | --- | --- |
| 主な遊び | 現実の行動を記録し、EXP・レベル・クエスト・連続日数を進める | 3D草原を探索し、敵と戦ってEXP・アイテムを得る | Web版の行動記録ループを採用。3D探索・戦闘は対象外 |
| 進行と報酬 | アクション、日次クエスト、マイルストーン、ステータス | 戦闘EXP、レベル、アイテム・装備・通貨 | 行動EXP、レベル、日次クエスト報酬に限定 |
| 保存 | バージョン付きlocalStorage、JSON退避・復元、Supabase同期 | ローカルJSONセーブ。Web版とはLEVEL/EXP/装備の共有同期も可能 | ローカル保存・移行・退避/復元を先行。クラウド同期は後続 |
| 個性付け | 目標入力、質問式ステータス/職業診断 | プレイヤー名とゲーム内ステータス | 既存Web版のオンボーディングと職業診断を優先 |

### 依存順のタスク

1. **MVP仕様を確定する** — 行動記録の最小項目、EXP付与、日付境界と連続日数、日次クエストの更新・報酬、保存/復元の受け入れ条件を定義する。既存Web版の保存データ互換が必要かも確認する。
2. **既存体験とデータを対応付ける** — Web版のプロフィール・職業診断・アクション・進行状態を調査し、初回リリースで維持する項目と移行しない項目を決める。Unity/iOSの構成は要件確認後に選ぶ。
3. **ローカル進行と保存を用意する** — バージョン付き保存形式、起動時復元、データ移行、退避/復元を実装・検証する。後続機能はこの進行モデルを利用する。
4. **行動記録とEXP/レベルをつなぐ** — 行動の選択・記録、報酬表示、レベル進捗、重複記録の扱いを実装する。
5. **日次クエストと連続日数をつなぐ** — 行動記録を入力として日次進捗・達成報酬・連続日数を更新し、日付変更や同日の複数記録を検証する。
6. **オンボーディングとiPhone実機相当の使いやすさを仕上げる** — 目標と職業診断を最初の行動記録に結び付け、画面サイズ、タップ操作、再起動後の継続、オフライン利用を確認する。
7. **同期の必要性を評価する** — ローカル保存を確認した後、アカウント、クラウド同期、競合解決、既存Web/Godotとの共有範囲を別途決定する。

**未決事項:** Web版の既存データをUnity版へ移行する必要性、EXP/クエストの具体的なバランス、日付境界・タイムゾーンの扱い、クラウド同期の初回リリース要否、iOS配布・ネイティブ機能要件。これらは既存コードだけでは決められないため、Unityの技術仕様として断定しない。

## 運用メモ

- 仕様が曖昧な項目は議論を Issue に残す
- 実装時の判断は完了条件に紐づけて記録する
- すべての変更は、関連する Issue と PR で追跡できる状態を保つ

## 今後の整理対象

- 合意したMVPに基づく開発スケジュールの仮設計
- GitHub Projects の自動化ルール
- 責務ごとの担当分担
